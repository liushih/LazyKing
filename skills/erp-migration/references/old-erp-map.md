# 旧 ERP 模块索引（模板）

本项目自己的模块清单填在这里。文件还是模板时，先按下面各表填完再开始取证。

动手前用 `ls modules/<模块>` 核一眼目录形态，本文件不是真相。

格式示例见同目录 `old-erp-map.example.md`。示例里的模块名属于另一套旧仓，不要拿来当本项目的候选。

## 后端模块

主站、分站各一张表：

| 模块 | 框架 | 控制器数 | 大致范围 | 新系统落点（按包名核对，不是猜） |
|---|---|---|---|---|
| `<模块>` | Laravel / ThinkPHP / 其他 | | | `<新模块>` |

控制器数用 `find modules/<m>/app/Http/Controllers -name "*.php" | wc -l` 现算。

## 前端模块

| 模块 | 形态 | 页面入口 |
|---|---|---|
| `<模块>` | React / Vue / TS / uni-app | `app/pages/<域>/` 或 `src/` |

**业务页面基本都在前端模块里**，不在后端模块的 `resources/views`（那里通常只有导出、邮件、工具页模板）。

## 分站差异

- 分站模块命名不保证与主站一致，列清对位关系
- 主站有、分站没有的模块单独列
- **库名可能与主站相同**，连库前确认实例，不能按库名判站点

## 数据权限

哪些模块有 `app/Scopes`，哪些写在控制器查询里（搜 `byDataPermission` / `scope`）。没有 `app/Scopes` 不等于没有数据权限。

## 连库

`config/database.php` 每模块的连接类型与库名来源。连接信息在部分模块的 `测试环境.env` / `demo环境.env`，账号密码不进任何文档。

## 新系统对位

- 后端各模块与包根
- 前端源码根
- 判断「新系统有没有」读代码，别看模块名；用包名搜关键词最快：`find <新后端根>/<m> -path "*controller*" -iname "*<关键词>*"`
