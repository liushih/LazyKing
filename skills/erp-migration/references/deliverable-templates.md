# 交付物模板

迁移说明书、覆盖矩阵、废弃清单给实现用。功能说明给汇报和转述，待确认清零且废弃、矛盾口径都已回写后再写，不等功能实现；子域拆分时每个子域一份。四份都放 `docs/migration/<域>/`。照骨架填，别每域重立格式——取值和统计口径固定，产出才能横向对比。

## 覆盖矩阵

状态只能取这 6 个值：

| 状态 | 含义 | 计入分母 |
|---|---|---|
| `已有` | 新系统已实现且行为与旧系统一致（或差异已写明并接受） | 是 |
| `部分已有` | 有页面/接口，但口径、列、权限或推送行为不一致 | 是 |
| `规划中` | 新系统没有，本期要做 | 是 |
| `本期不做` | 建议不做；**未确认前写 `本期不做（待确认）`** | 否 |
| `不迁` | 不搬数据/不搬实现（含已注释、已废弃的表） | 否 |
| `待确认` | 证据不足，判断不了 | 否，且必须在头部的待确认条数里体现 |

```markdown
# <域> — 覆盖矩阵

统计：本期要做 N 项（已有 a / 部分已有 b / 规划中 c），本期不做 d，不迁 e，待确认 f。
覆盖率 = 已有且行为符合 / 本期要做 = a/N。

| 功能点 | 取证 | 新系统 | 证据 |
| --- | --- | --- | --- |
| 按平台进入列表 | `modules/erp_html/app/pages/Publish/StockSynchOnline/index.jsx`，路由带 platform | 规划中 | 新页面无平台参数 |
```

规则：

- **取证**列写旧仓相对路径（带 `modules/<模块>/` 前缀）或 `表.字段`；金额、状态迁移、库存数量要细到方法
- **证据**列写新系统的判断依据，不只写结论；「部分已有」必须写清哪部分缺
- 一行一个功能点，功能点按「用户能做的动作」切，不按代码文件切

## 迁移说明书

```markdown
# <域> — 迁移说明书

汇报用的功能说明见同目录 `<域>-功能说明.md`。

## 1. 域边界与交接
模块清单（旧 `modules/<a>`、`modules/<b>`；前端 `modules/erp_html/app/pages/<域>`）
作用：谁用、上游交来什么、下游谁读
角色与单据、域内外分界

## 2. 功能取证与覆盖矩阵
（逐类取证结论，链接到覆盖矩阵；不重复贴整张表）

## 3. 实体、状态机与流程闭环
### 3.1 旧表（库 `<库名>`）
### 3.2 新系统表
### 3.3 状态
### 3.4 主流程 / 逆向流程 / 异常分支

## 4. 上下游数据关联
单据 DAG、字段血缘

## 5. 规则清单
校验、编码、单位精度、权限点、审批流、库存占用
### 5.x 并发、事务、幂等

## 6. PHP → Java 语义差异
（只写本域命中的，不抄通用清单）

## 7. 合理性评估
A/B/C/D 逐条带理由

## 8. 数据影响与同步结论
同步结论四选一 + 数据量 + 时间水位 + 过渡期写入方 + 切流
基础数据前置清单
报表与指标清单（含 SQL 出处）
```

必写四项（缺任一不算完成）：功能在项目中的作用、旧项目表（`库.表`，写清存什么/谁写入）、重构项目表（没有就写「尚无」+ 拟落表）、同步结论。

不要把「主数据已在」写成「这个功能的数据已在」。

这些不是废弃，是旧系统自己两套行为。新系统按下面取，避免两套数。

| 矛盾 | 实际两套行为 | 新系统 |

## 子域拆分清单（域较大时）

`docs/migration/<域>/README.md`，跨会话靠它续跑：

```markdown
| 子域 | 单据范围 | 状态 | 说明书 | 功能说明 |
| --- | --- | --- | --- | --- |
| <子域 A> | | 已完成 | `<域>-<A>-迁移说明书.md` | `<域>-<A>-功能说明.md` |
| <子域 B> | | 进行中（§3 未写） | | |
```

状态只用：待做 / 进行中（写清停在哪节）/ 已完成。

## 实现任务清单（说明书末尾）

每条对应覆盖矩阵的一行或一组行，按依赖排序，写明工作区、分支、基线：

```markdown
## 实现顺序（本分支）

工作区：`<path>`，分支 `<branch>`，基于 `test`。

1. <任务>（矩阵第 3、4 行）
2. <任务>（矩阵第 7、9 行）
```

末尾一句「要开始实现说一声」。

## 功能说明（汇报用）

文件名 `<域>-功能说明.md`，子域拆分时为 `<域>-<子域>-功能说明.md`。待确认为 0、废弃清单和矛盾小节里的口径都已按用户结论回写之后生成。取证中途、还有待确认时不写。不等功能实现完再第一次写。实现之后代码与已确认口径不一致时改代码，只有用户重新确认口径才改本文件。

不写取证路径、矩阵状态、PHP 行号、实现任务。

```markdown
# <域> — 功能说明

任务 <编号>。给汇报和转述用。实现细节见同目录迁移说明书、覆盖矩阵、废弃清单。

## 1. 精简功能说明

能做的事、不做的事。一张表写清本域有哪几种单据、各自什么时候出现、结果落到哪。

## 2. 流程图

用 mermaid 画正向主流程。作废、退回等逆向用一段话写在图下，不塞进主图。

## 3. 功能作用

谁用、解决什么、在整条单据链里处在哪。上游交来什么，下游谁读。

## 4. 数据上下游与流转

一张 mermaid 图：上游主数据 → 本域单据 → 下游。图下按时间顺序写数据怎么从一张单流到下一张，含状态回写和自动生成的下游单。
```
